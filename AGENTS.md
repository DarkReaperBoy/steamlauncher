# AGENTS.md

NixOS flake (nix-crab, continued from ItszFinn/nix-crab) that makes SLSsteam injection, Millennium *or* LuaTools, per-game Steam config, ACCELA, SteaMidra, netsock and the Steam client-downgrade tool declarative. Everything a user writes is one `programs.nix-crab.*` block in plain NixOS config — **there is no home-manager anywhere in this flake** (not an input, not a module import, not a requirement). CloudRedirect is gone; steam-config-nix is re-exported. Published **public** at <https://github.com/DarkReaperBoy/steamlauncher>: keep the tree free of secrets and personal paths, and expect CI to be cheap (public repos get unlimited Actions minutes).

## Architecture

- **One namespace**: `programs.nix-crab.*` — including Steam itself. `steam` is a single option: `steam = true` is sugar for `enable = true`, `steam.{enable,package,extraPkgs,extraCompatPackages,config}` are typed, and every *other* upstream `programs.steam` option (`remotePlay.openFirewall`, `protontricks`, `dedicatedServer`, …) is written under `steam.*` freeform and forwarded verbatim — upstream's types/docs stay authoritative. `steam.config` is a thin alias of steam-config-nix's `programs.steam.config` (`modules/steam-config.nix`).
- **Unit pattern**: `modules/<feature>.nix` is `{ inputs }: { module, mk* }`; `flake.nix` instantiates each once, `.module` for module outputs, `.mk*` for `packages.*` — one definition per derivation. Modules owning no derivation (`settings.nix`, `options.nix`, `steam-config.nix`, `netsock-bridge.nix`, `millennium*.nix`, `user.nix`, `target.nix`, `activate.nix`) are plain or pure functions. Do not recreate `lib.nix`.
- **Options/config split**: `modules/options.nix` declares every user-facing option ONCE (plus `settings.nix`); the per-feature modules only emit config.
- **Target user**: `modules/target.nix` is a *function* (`{ config, lib }: { user, home, normalUsers }`) imported by each feature module — one resolution rule (explicit `programs.nix-crab.user`, else the single `isNormalUser`), no shared option. `modules/user.nix` declares the `user` option and the cross-feature assertions.
- **User files**: `modules/activate.nix` wraps a shell body as a `system.activationScripts."nix-crab-<name>"` entry (deps `specialfs users`); packages go to `environment.systemPackages`. Nothing writes `users.users` or `home-manager.users`.
- `nixosModules.default` = steam-config-nix's NixOS module + `options.nix` + `user.nix` + `netsock-bridge.nix` + `millennium.nix` + `slssteam.nix` + `downgrade.nix` + the five feature units + `millennium-addons.nix`. **There is no `homeModules.default`** — it was deleted with the home-manager input.
- Units are partial applications: `flake.nix` threads inputs (`(import ./modules/x.nix { inherit input; })`). Never use `inputs` inside a module body.

## Decisions — do not "fix"

- **No home-manager, at all.** The `home-manager` flake input, `homeModules.default` and `nixos-home.nix` (the old NixOS→HM forwarding) are gone by explicit user request ("no home manager at all, for configs or anything else"). User-scoped effects are applied two ways:
  - **Files** → activation snippets via `modules/activate.nix`: target user/home baked at eval time, body runs in a `( set -eu )` subshell with `HOME`/`USER`/`LOGNAME` exported, an absolute `PATH` (coreutils…yq-go via `makeBinPath` — NixOS activation runs with `PATH=/empty` + system profile only), `run` (pass-through, dag familiarity) and `own` (chown to the target **only when root**, so the same text runs unprivileged in tests). Failures print `activation snippet '<name>' failed` and set `_status=1` — the variable NixOS' activate script traps on; they do NOT abort the switch.
  - **Packages** → `environment.systemPackages`, **never `users.users.<user>.packages`**: the gate resolves the target user and resolution reads `users.users`, so writing `users.users` from a user-dependent path recurses (the same trap as home-manager#594, which the old nixos-home.nix documented).
  - Consequences: a snippet body must NOT use `return` (it runs inline in a subshell, not a function — only `return` inside a shell function defined *in* the body, like `crabSync`, is valid); `systemd.user.services` uses NixOS' flat schema (`description`/`after`/`wantedBy`/`serviceConfig`), not HM's `Unit`/`Service`/`Install` sections; do not reintroduce HM "just for the home side" or a `homeModules.default` alias.
- **`programs.nix-crab.steam.*` owns the official Steam module** — one `steam` option (either bool or submodule, `apply` normalizes `true` → the attrset; `steamDefaults` in `modules/slssteam.nix` is the single source of the submodule defaults so the bool branch has every key readers touch). `enable`: null = on when a feature needs it (`slssteam`, `slssteam-moon`, `millennium`, `steam.config`); `package`: the base injection is built *from* (Millennium's `millennium-steam` when `millennium.enable`); `extraPkgs`: fed into the ONE `steamBase.override` this flake performs — this option exists precisely so nobody needs the old `nixpkgs.overlays` extraPkgs workaround (`programs.steam.package` is types.package and rejects two definitions).
  - **`extraPkgs` function values arrive functor-wrapped**: `types.functionTo`'s merge returns `{ __functor; __functionArgs; }`, so `builtins.isFunction` is false for it — the consumer must use `lib.isFunction`, or the list branch feeds the set to `++` inside nixpkgs' steam ("expected a list but found a set"). Both forms (plain list, `p: [...]`) are supported and tested.
  - Freeform passthrough keys are `removeAttrs steamCfg [ enable package extraPkgs extraCompatPackages config ]` — keep `extraCompatPackages` in that list or it is forwarded twice (concat duplicates).
- **Options that are typed but not written default to `null`** — `settings.*` per-key options (`modules/settings.nix`, mirrors upstream's `config.yaml` incl. slsteam-moon's `ManifestPins`), `accela.config.*`. `extraSettings` is the freeform escape hatch. Setting any `settings` key without `manageConfig` fails eval.
- **The managed `config.yaml` is written by an activation snippet, never a store symlink** — SLSsteam's watcher and the LuaTools plugin (temp-file+rename) cannot write through one. Real 644 file next to the target, `mv` in (replaces a legacy symlink by rename inside one directory), only when content changed (`cmp -s`), plugin-owned keys carried over first.
- **Merge base = the active fork's own `res/config.yaml`**, deep-merged with `pkgs.yq-go` (`base * overlay`). Never `pkgs.yq` (kislyuk's jq wrapper), never a hand-written YAML renderer, never yq for an EMPTY overlay (nulls → `''`, flow style). Plugin-owned keys (`ManifestPins`, `FakeAppIds`) are carried over from the live file each activation unless the user declared them; extraction must strip comment lines.
- **`DisableCloud: true` is the one flake-level default** — both forks ship `no` because they normally ship a cloud hook; CloudRedirect is gone. User values win.
- **`manageConfig` defaults false** so SteaMidra can own the file.
- **Upstream release binaries, not source builds** — five projects: SLSsteam, Millennium, slsteam-moon, Lumen, LuaTools (`modules/upstream-binaries.nix`). `upstream.lock.json` is **generated** by `ci/update-binaries.sh` (never hand-edit: it verifies each asset against the project's own `.sha256` sidecar, and falls back to the fetched hash when a project publishes none — SLSsteam doesn't). Four flake inputs were deleted for this; with home-manager also removed, only **6** remain (nixpkgs, millennium, steam-config-nix, enter-the-wired, steamidra, steamnetsock). Consequences to remember:
  - `sls-steam` is unpacked from `SLSsteam-Any-release.7z` and **must keep the store name `sls-steam-*`** — `nix-crab-status` detects the injected fork by matching that name in `LD_AUDIT`.
  - `ticket-grabber`/`schema-grabber` are framework-dependent .NET 9 publishes from the same 7z; their wrappers only set `DOTNET_ROOT` to `pkgs.dotnet-runtime_9` (the exact store path upstream's own wrapper uses). Nothing compiles in CI at all — the sync job's "build" step is seven unpacks.
  - the managed-config merge base for *both* forks now comes from the same archive as their binaries (`<pkg>/res/config.yaml`).
- **Millennium wiring**: `modules/millennium.nix` applies *two* overlays — Millennium's own, then one that replaces `final.millennium` with the release binary. `millennium-steam` is defined in terms of `final.millennium`, so it picks the swap up with no other change. Never remap `pkgs.steam = millennium-steam` (recurses).
- **`.github/workflows/ci.yml` is intentionally small — no cache, no builds.** Since every heavy artefact is an upstream release binary there is nothing to compile and nothing worth caching: `magic-nix-cache-action` was removed after it left ~2300 entries in the repo's Actions cache (storage the user pays for). `check` = `nix flake check` + `nix fmt && git diff --exit-code` on every push/PR, with `tests/` added **only on pull_request** so ordinary pushes stay ~30 s (measured: 32 s per push, 38 s for the sync job). `sync` (daily 04:17 UTC + manual) = `ci/update-binaries.sh` → `nix flake update` → `nix flake check` + unpack the seven release binaries → PR (job-summary fallback if the repo's Actions-PR setting is off). Actions are SHA-pinned; `timeout-minutes` on both jobs. Do not re-add a cache — there is nothing built worth caching.
- **CloudRedirect is gone** (upstream repo, `-moon` fork, CLI, Flatpak, `nix-flatpak` input, `~/.local/share/CloudRedirect/*`). `slssteam.extraEnv` is the escape hatch for a preload library.
- **netsock is never injected globally** — `~/.config/SLSsteam/tools/netsock/netsock.so` + per game only, never with anti-cheat.
- **`steam-run` must stay in the luatools module's packages** — the Lumen shim execs it; `programs.steam` does not provide it.
- **No "Steam with SLSsteam baked in" package**; injection only exists behind `programs.nix-crab.slssteam.enable`. No package output is unfree.
- **Forge inputs**: `steamidra` = `api.github.com/repos/Midrags/SFF/tags` (releases/latest changes hourly → narHash churn; never pin `narHash` either). `enter-the-wired` = the AppImage in the store (versionless URL, no tags). `accela`/`steamidra` AppImages: SteaMidra is downloaded at runtime by the launcher, ACCELA is an `appimageTools` wrapper needing `extraPkgs = p: [ p.zstd ]`.
- **`downgrade.nix`**: `dgsc`/`dlm` pinned to commit `8c36338994fdb085fa07b887f71d64362af51c1d`; manifest + `sources.txt` are fetched at runtime with curl (fetchurl hashes rot every Steam build).
- **`ACCELA.conf` is seeded, never managed** (QSettings rewrites it) — same reasoning as `manageConfig`.
- **`luatools.lumenService`** is an opt-in alternative to the `steam` wrapper sidecar; never both. The user unit starts at login like any NixOS user unit (there is no HM `startServices` to nudge it).

## Verification

- `nix flake check` in repo root. `nix fmt` before committing (nixfmt does not touch `''` string interiors — heredocs in activation bodies are safe).
- Tests live **in-repo at `tests/`** (`cd tests && ./test-eval.sh && ./test-writer.sh`), run by the `check` CI job **on pull requests only**. The harness flake consumes this repo via `path:..`, recorded in its lock *without* a narHash, so it always evaluates the current checkout; there is nothing to re-lock after edits (the scripts run `nix flake lock --update-input crab` themselves anyway). Configs: `nixosConfigurations.{bare,full,moon,steamOnly,steamPkg,steamSugar,steamPassthrough,smokeNixos,writerSmoke,writerFake,ambiguousUser,explicitUser,badCombo,badSteamOff,badSettings,badNetsock}`. There are **no `homeConfigurations`** — the eval suite asserts home-manager is absent (option + lock). `bare` must leave Steam off with no file-writer snippets (`nix-crab-millennium` IS present with empty lists by design — emptying must keep running); `bad*` must fail eval with the intended assertion message; `full` must show `LD_AUDIT` and `MILLENNIUM_RUNTIME_PATH` on the same steam package.
- **Writer tests run the real activation text**: `test-writer.sh` extracts every `system.activationScripts."nix-crab-*".text`, wraps it in a driver that mirrors NixOS' activate script (`trap "_status=1 …" ERR`, `exit $_status`) and runs it against sandbox homes (`/tmp/hm-test`, `/tmp/hm-test2`, `/tmp/hm-nixos`). Never go back to building an HM `activationPackage`.
- Sanity for binaries: `nix build .#sls-steam .#ticket-grabber .#schema-grabber .#millennium .#slsteam-moon .#lumen .#luatools` (seven unpacks, no compilation), and `./ci/update-binaries.sh` must report "everything already current" when the lock is right.
- The LuaTools plugin's line regexes must keep matching the generated file: keys bare (`  123:`, `  440: 480`), never `'440'`.
- `steam.extraPkgs` is verified by building `steamPassthrough`'s package and finding `hello` in the FHS closure (`hello` is nowhere in steam's own env, so presence is decisive).

## Gotchas

- **Path-input narHash**: consumers via `path:...` must re-lock after every edit here.
- **`programs.steam.package` has an upstream `apply`** (NixOS re-overrides the package), so its final drv never equals the raw definition — compare configurations, not paths.
- **No backticks inside double-quoted test strings** — `` `steam = true` `` in `test-eval.sh` executed `steam` and hung the suite for 40 minutes.
- **`nix eval --raw` cannot print a boolean** — use `--json` (or read the value out of the coercion error).
- yq-go: no `&&`/`||` (use `and`/`or`), no "plain" style, `-o=json` overlays poison a YAML merge. Keep every intermediate in the pipeline YAML.
- `appimage-run` smoke test: `HOME=$(mktemp -d) QT_QPA_PLATFORM=offscreen accela`.
- `modules/steam.cfg` `BootStrapperForceSelfUpdate` typo was fixed; keep it `disable`.
